
### 進上クッキング (Shinjoh-Cooking)

**自律型レシピ生成 ＆ 動的リカバリー調理エンジン** 

### コア・アーキテクチャ（3層構造）

機能の無駄を徹底的に削ぎ落とした、安全かつゲーム感覚で料理ができる自律型システム。 

[食材・調味料の入力]
       │
       ▼
 1.【レシピ生成AI】 ──> 入力された食材から自律的にレシピを組み立てる
       │
       ▼
 2.【ダブルチェック・フィルター】
     ├── ① 内部監視AI：調理手順の矛盾やハルシネーション（嘘）を検知
     └── ② アルゴリズム：アレルギー物質の排除、最低加熱時間の厳密な強制ルール
       │
       ▼ (審査を通過)
 3.【ゲーム型UI ＆ 動的リカバリーエンジン】
     └── リアルタイム調理画面（例：「ステップ1: 肉を取り出す 残り30秒」）
           │
           ├── [完了ボタン] ──> 次のステップへ
           └── [中断ボタン] (遅延・材料ミス発生) 
                 └── ① 注意すべき点（生焼けリスク等）を一最優先で出力
                 └── ② 残りの手順をAIが自動でリアルタイムに再調整！

### 🛠️ システム詳細仕様

### 1. 入力データ

* 利用可能な食材・調味料: 冷蔵庫や家庭科室にあるもののリスト
* ユーザーのアレルギー: アルゴリズム層で強制的に調理工程から排除する物質

### 2. ダブルチェック・安全レイヤー

生成AIのミスや危険な手順を絶対に発生させないための防衛線。 

* **内部監視AI:** 「この手順で本当に料理が成立するか」「加熱指示が不自然に抜けていないか」をチェック。
* **コードベースのルール:** 「豚肉は最低〇分加熱」「アレルギー食材の文字が含まれていたら即エラー」など、決定論的なプログラムで安全を担保。

### 3. 動的リカバリーエンジン

料理を絶対に失敗させないための核心ロジック。 

* 調理者が「中断」を押した場合： 

  1. **危険・警告チェック:** 「生焼けの肉を放置しないでください」などの最優先のアラートを表示。
  2. **レシピの再計画:** 現在の遅れや間違えた材料の状況をプロンプトに自動で組み込み、お父さんのAPIを使って残りの工程の最適解を再計算。

### 📅 週末の最小目標（MVPターゲット）

まずは機能を極限までシンプルに保ち、自分自身が家庭科の授業や家で使うためのプロトタイプを完成させる。 

* [ ] **ステップ 1:** 新しいリポジトリを作成し、この仕様書をコミットしてセーブする。
* [ ] **ステップ 2:** 食材リストからレシピを綺麗に出力させる基本プロンプトを固定する。
* [ ] **ステップ 3:** アレルギー物質を文字検索で弾く、シンプルなPythonのフィルター関数を書く。
* [ ] **ステップ 4:** 1ステップずつ「残り秒数」と「完了／中断ボタン」が出る、ターミナル（CUI）または簡易的な画面を構築する。
* [ ] **ステップ 5:** 「中断」が押された際、状況をAIに送り直して手順を再構成するリカバリー処理のテスト。
